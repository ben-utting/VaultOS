# VaultOS Round 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put a "Next" strip at the top of Today, give each gold mark one meaning, and replace the icon-only toolbars in the task drawer and the Files bar with labelled actions plus a More menu.

**Architecture:** There is no build step. `public/*.js` are classic scripts sharing one global scope; `today.js` loads after `app.js` and can use its top-level `STATE`, `TASK_AGENTS`, `openTask`, `api` and `esc`. New logic that can be pure goes in small UMD modules shaped like `public/agent-form.js`, so `node:test` can load it. Work happens in the worktree `/opt/vault/board-r2` (branch `round-2`) and is checked on a throwaway preview. The owner merges each part, and the merge is the deploy.

**Tech Stack:** Express 5, vanilla JS, one tokenised `public/styles.css`, `node:test` (run inside the `vault-board:latest` image), and puppeteer from the npx cache for browser checks.

**Spec:** `docs/superpowers/specs/2026-10-30-round-2-design.md` (approved 2026-10-30).

## Global Constraints

- Tone: precise, not louder. No new colours, gradients, shadows or ornament.
- Fonts use only the `--t-*` tokens, with a 12px floor. Text is ≥ 4.5:1 in dark and sepia. Solid gold stays limited to the allowlist in `test/look-tokens.test.js`, and that test must stay green.
- Use "workspace" in UI copy.
- Keep CLAUDE.md's "don't undo" behaviours: `holdScroll` pairing, refresh feedback, subtask fold, lazy-load guards, `pollBoard` skipping mid-drag.
- **Preview runs the live feature flags (`TERMINAL=1`).** Every header, toolbar and drawer fit check includes the Terminal button.
- **Never touch the live app:** `/opt/vault/board` main, container `vault-board`, port 7684, or the real vault `/opt/vault/vault`. Never merge, push or restart `vault-board`. The controller hands the owner a one-line `!` command.
- **Run tests in the image:** `source /opt/vault/r2-check/T.sh; T '<glob>'`. 7 suites fail on main as a known baseline (/opt/vault/r2-check/baseline-failures.txt); nothing else may fail.
- The repo is public. The controller runs the private-words check (`scripts/private-words.txt`) on the added lines before a push.
- Commit messages end with a blank line and then `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Next while the timer runs or is in a break:** Start shows `Running · mm:ss` and is disabled, the strip never starts a second session, and Open still works. (Task 2 check.)
2. **Viewing another day (‹ arrow):** Next shows that day's first open task and never the Board fallback. (Task 1 test and Task 2 check.)
3. **Switching workspace while on Today:** Next re-fetches for the new workspace. A slow answer for the previous workspace is dropped rather than painted. (Task 2 check.)
4. **A today task or board title with HTML characters, or one too long for a 390px phone:** it shows escaped text and truncates with an ellipsis, so Next never grows past two lines. (Task 2 check.)
5. **A More menu open while its owner goes away** (the drawer closes, the Files tab switches, or the mode changes): the menu closes too, and focus is not left on a detached node. (Task 4 and Task 5 checks.)

### Task 1: `pickNext` — the pure Next picker

**Files:**
- Create: `public/today-next.js`
- Create: `test/today-next.test.js`
- Modify: `public/index.html` (add `<script src="today-next.js"></script>` immediately before `today.js`)

**Interfaces:**
- Produces: `TodayNext.pickNext({ todayTasks, boardTasks, agentState, viewingToday, wsLabel }) → Next`. The arguments are:
  - `todayTasks: Array<{ text: string, done: boolean, moved?: boolean }>`
  - `boardTasks: Array<{ title, path, status, mtime }> | null`
  - `agentState: (path) => string | undefined`
  - `viewingToday: boolean`
  - `wsLabel: string`

  `Next` is one of:
  - `{ kind: 'today', text, target: 'task:' + text }`
  - `{ kind: 'board', title, path, wsLabel, needsYou: boolean, target: 'task: ' + title }`
  - `{ kind: 'clear' }`

- [ ] **Step 1: Write the failing tests** in `test/today-next.test.js` (`const TN = require('../public/today-next')`):
  - `the first open today task wins`: with `todayTasks [{text:'a',done:true},{text:'b',done:false},{text:'c',done:false}]`, `kind` is `'today'`, `text` is `'b'` and `target` is `'task:b'`, even when `boardTasks` holds an in-progress task.
  - `moved today tasks are skipped`: `{text:'x',done:false,moved:true}` is ignored.
  - `board fallback takes in-progress only`: with board statuses `backlog`, `review` and `in-progress` (title `'P'`), `kind` is `'board'`, `title` is `'P'`, `target` is `'task: P'` and `wsLabel` is passed through.
  - `needs-you beats a newer task`: two in-progress tasks. The older one has `agentState(path) === 'blocked'`, so it wins and `needsYou` is `true`.
  - `otherwise the newest mtime wins`, and `needsYou` is `false`.
  - `no board data means clear`: `boardTasks: null` with no open today task gives `{kind:'clear'}`.
  - `nothing left means clear`.
  - `another day never falls back to the board`: `viewingToday: false`, no open today task and an in-progress board task give `kind` `'clear'`. With an open today task it still gives `'today'`.

- [ ] **Step 2: Run them to confirm they fail.** Run `source /opt/vault/r2-check/T.sh; T test/today-next.test.js`. Expected: FAIL, "Cannot find module '../public/today-next'".

- [ ] **Step 3: Implement `pickNext`** in `public/today-next.js`, using the UMD wrapper copied from `public/agent-form.js`'s head and tail.
